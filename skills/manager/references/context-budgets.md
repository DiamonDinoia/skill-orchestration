# Context budgets

Load mandates cost context. In a quick one-shot consult, load only the skills the question needs: a fast consult carrying broad tool permissions plus several standing rule-sets over-acts past its question, and a light brief fixes scope where permissions do not. A child that loads several full skill texts and then reads a large file can overflow before work starts; the symptom is a context-length failure right after setup. For a large-file job the brief says which skills the child skips loading, bounds the reads (grep the named functions, read with offset and limit), and routes long command output through tail. The write side needs the same bound: for an edit to a single large artifact (a thousand-line doc), the brief caps how many lines one response or one write may carry (about a hundred) and orders targeted patch calls block by block; a child that answers with one giant rewrite of the whole file dies mid-write and loses the deliverable.

- A node with many sequential gates (measurement runs, emulated legs, CI cells) risks the harness call cap mid-verification; the brief then carries budget rules: batch several shell steps per call, wait on process exit instead of polling, and send each mechanical leg to a cheap-tier leaf.
