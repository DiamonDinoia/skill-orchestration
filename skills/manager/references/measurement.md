# Measurement rules

- A replacement for an existing parser or scanner gets a corpus-level equivalence check, not only unit rows: chunk real files, run the old implementation in a worker with a per-chunk timeout (materialize it with `git show <sha>:<path>` into the scratch dir and import it by path; never check out its branch in a live tree), and require zero differing outputs. A chunk that hangs the old side is a pathological-input finding, not a check failure.
- A threshold or constant tuned by a measurement node lands in code with a comment naming that measurement. A bare number reads as arbitrary; the comment lets a reviewer rerun the measurement instead of trusting the value. The named measurement must be rerunnable by the reader: cite a repo script, a console artifact, or the measurement conditions. A comment that names a scratch file the reader has no access to fails the reader the same way a bare number does, and a derived share the artifact cannot reproduce (a share the consoles cannot time) reads as verified when it is not. The reviewer rejects both.
- A measurement or sweep brief caps its own size in the text: runs per level, the level list, the pause between runs, the total budget. An open-ended sweep lets the child pick a grid that burns its deadline on data nobody reads. The probe appends one CSV row per cell as it measures, so a kill loses only the in-flight cell and a rerun resumes from the partial file. The same append-during-work rule holds for a long findings or audit report (cited excerpts, a per-finding table, a recon claim list): the child writes each phase's rows as it finishes them, so a dead child leaves a usable partial findings file on disk and the rescue recovers state from it instead of re-reading from zero. A resumed partial file carries a stamp of the rule files that produced its rows (a content hash over the scoring sources); a rerun whose stamp mismatches refuses with a nonzero exit instead of mixing two rules' rows, and never deletes the file on its own.
- A new automated block stacked beside an existing block gets an added-value row in its sweep: the count of catches that no existing block triggers. Zero added value means the stack is a no-op, and the fix is design, not tuning. Score the full shipped rule, signal plus downstream gate. A sweep of the signal alone can show catches that the composed rule removes.
- A deciding experiment between candidates that score the same on the corpus reports wall-clock cost for each on a real input. The tie breaks on that cost, not on elegance.
- A measurement tells the user what the tool costs, so it times the tool alone, one probe on the box at a time. Timing a live agent session mixes in the harness (turn serialization, per-harness filesystems, their caches) and answers a question nobody asked; gate end-to-end behaviour with one canned agent turn instead of sweeping it.
- A recon or research report that gates design is a claim list, not a fact base. Enumerate each design-critical claim as C1, C2, ... and dispatch one read-only verification node before build nodes depend on it: the child pins HEAD by sha and reads sources with `git show <sha>:<path>` (dirty-tree edits cannot pollute the check), then answers per claim TRUE / FALSE / PARTLY with file:line and one quoted line. A false "the tool lacks X" premise costs whole build rounds; the node answers that claim shape by grepping the tool for registries, caches and matching passes and quoting every hit. Missing machinery is the premise a careless recon invents. A recon that also proposes fixes still leaves its root cause unverified in this way: a fix brief written straight from it lands one level above the real mechanism.
- A summary ratio can hide a failing tail. Before an adopt call, require each candidate's full outlier rows with pass/fail lines. A user-inspected plot beats the aggregate.
- A shared-mechanism diagnosis gets parallel single-variable children: dose-response, error budget (one approximation off at a time), acceptance question. Each child replaces every component but its own with an exact reference, so each measured number bounds one mechanism: the fit alone against an exact reference, the reconstruction alone from an exact reference. A cause a child quotes as untested (an internal sampling grid, a rounding step) is a hypothesis; route it to such a child before relaying it as a finding.
- Mid-decision updates to a tool that several running children resolve by command name (a version manager's default channel) can flip versions between a child's setup run and its measuring run. One job owns the update and the brief names the owner; every other consumer child re-checks the resolved version before its final numbers and reruns on change. The reports name the version used for every number.
- A native-code dependency evaluated for adoption by the repo gets validation nodes in supported-shipping configuration: build flags as the shipped release builds them (a dispatch or multiarch CMake preset), not a perf-optimal local default such as `-march=native`, so the numbers match what users get. Confirm the shipping default on the upstream default branch at clone-or-fetch time (the local clone can lag, the release-workflow yaml answers in one read) and, for runtime dispatch libraries, time one forced rung below the host's best ISA (the env override the dispatch code reads) as the low-end number. A scalar-call cost through the language binding (ccall, ctypes, an FFI boundary) can dominate the kernel itself, so the microbenchmark measures the scalar call, the batch call and the per-element loop the host code would really use, at the batch sizes the host data structures give, before an adoption call counts any speedup. A profile's inclusive share of a hot kernel names the opportunity; it says nothing about which call form pays off, and a fit that loses to the host's own implementation at the host's own error is a no.
- A profile of a language whose compiler inlines by default (Julia, C++, Rust) understates every hot kernel in its self-time: the inlined body charges to the caller's frame while the kernel name keeps only samples above the threshold. Derive the kernel's share from inclusive counts at the call sites and from per-line counts inside the function's own body lines (a flat profile's file:line rows), never from self-time alone; an Amdahl bound built from self-time reads an order of magnitude too small.
- A measurement brief names the metric, the target source and the target list. The child may not substitute any of them.
