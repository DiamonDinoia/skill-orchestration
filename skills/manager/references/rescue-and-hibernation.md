# Rescue and hibernation

A rescue child inherits the stopped child's leftover state, not its plan. That includes the runs the dead child already launched: when a launched sub-run's own log holds a final report and its exit line, the rescue judges that run and never relaunches it, because a rerun re-pays the full lane and its new output is not more trustworthy. Probe the leftover before writing the rescue brief, per repo or location the node owned: `git rev-parse HEAD`, `git log --oneline -3`, `git status --short`, diff stat, transcript keyword hits, and the scratch-dir file list. Its brief opens with that same probe list. A child that died mid-report may have landed zero, some, or all of its edits and commits; the quoted pre-state comes from this probe, never from the dead child's report fragment. The brief says what the rescue keeps, redoes or discards and why, and directs it to complete only what is missing. The rescue brief probes the leftover for internal inconsistency before any keep call: grep the touched files for both spellings of every renamed or moved symbol and run the build or linter; a stream stopped mid-write leaves definitions moved, duplicated or half-renamed, and the diff stat never shows it. A rescue after a model-output failure (an output loop, a truncated stream, raw `<function=...>` markup in the log where a tool call belongs) also changes the model, not only the brief: the same prompt to the same model reproduces the same stall. A lane log that ends with a clean exit line, no report and no model-error line gets its death classed from the harness session store before the rescue brief: the session's end_reason and last assistant message separate model-output corruption (broken markup, a mangled path string in the final tool call) from a lane the runtime closed, so the rescue swaps the model only when corruption is confirmed and otherwise fixes the brief or the runtime. A death the session store classes as a transient provider rejection (a gateway error with no fault on the child's side) gets one identical rerun before any model swap; the first write of a cold session can hit a provider quirk that never recurs, and one rerun costs less than a rescue. The raw-markup log line means the model's output broke the harness's tool-call serialization, so the turn ended without running its command and without a report. Its report opens the same way.

## Hibernation mid-brief
A child dead at the harness's iteration or call cap stops mid-step with uncommitted files and an origin tip that may not match its worktree (push races, baton passes). The rescue reconciles before it resumes: make a backup ref of any uncommitted work (`S=$(git stash create) && git branch backup/<name> ${S:-HEAD}`, the stashed change when there is one and HEAD when the command prints nothing), compare local and origin tips both directions with `merge-base --is-ancestor`, continue from the newer one by fast-forward only, and name in the report which tip won and why. Never force-push; never trust the dead child's summary over file and git state.

A paused job holds state in its brief and its scratch notes, not in the chat. The resume comes from the child that reads them, not from the user pasting the plan back. A redo after a failed start lists the old scratch dir first and salvages the files the redo still needs (lane scripts, seeded repos, archives); a blind `rm -rf` of the old dir throws away that work.
A rescue child that ends with no report is itself a crashed job. Check its log directory for artifacts, then `fail` its node and re-dispatch the rescue from the manager as a fresh leaf with full state. Do not trust a silent rescue, and never infer the crash point without the transcript tail.

A child session can be hibernated and woken between its own steps (the trace shows `System`**` Session took a break `**without a user message). On wake the child re-reads its brief and the worktree's `git status --short` before touching state. Old state greps and mutation plans can point at steps that ran during the nap. The report names the wake.

The same holds for the manager after its own wake. Reuse completed discovery reports; never re-pay discovery on stale fear. Re-probe only what a live brief anchors on (`status --short`, `rev-parse HEAD`), and `retry` the next graph node instead of re-dispatching finished nodes.

- Default child deadline is 60 minutes. Stop a hung child after two checks with no progress and liveness not running; unknown counts as running. Stop at the deadline too.
- The deadline stops a stalled child, not a producing one. A producing child past deadline keeps running, and the next report names the extended deadline. A child past 1.5 times its deadline gets a mid-run checkpoint request.
- Stop any child on user cancel or unsafe work. Leave every other child alone.
