## Review (required before handoff; GLOBAL rule)
Load the `brainstorm` and `team` skills with skill_view and follow them for this review. Do not create or edit skills or memory.
Small diffs get sol alone and skip this block; the order rule is in `references/review-loop-rules.md`.
1. Brainstorm, for diffs above 200 changed lines only. List at least 5 ways your change could be wrong. Cover edge cases, callers you did not touch, state leaks, config left changed, width, colour or terminal differences, and error paths. Settle each one in a decision-log row: | risk | verdict (real / not-an-issue) | evidence (one line) | fix |.
2. One fresh-context reviewer subagent (delegate_task) that did NOT write the code gets the review-brief, the diff (`git diff` / file paths) and the deliverable checks. Each review-brief has the goal and the change from the review-brief rule in skill `manager`. The reviewer runs the checks itself and returns ACCEPT or REJECT <reason>. Reviewers never edit the code or the branch. They can write scratch files and prototypes. The launcher reads the diff itself and reports that as the second opinion. Every delegate_task child counts toward `delegation.max_concurrent_children`; flatiron parallelism is unlimited otherwise. Do NOT spend a child on collection or counting; do that with your own tools first. If the budget runs out before the reviewer is done, say so in the report and finish the review inline in this session.
   Review output carries only BLOCKER and MAJOR findings (skill `manager`, rule T1). Log churn and deletion findings (PRUNE <file:line>) as follow-ups; a PRUNE never starts a fix round. A PASS-WITH-NITS closes the task with follow-ups logged.
3. Fix every REJECT and fix-round regression, re-run the checks, and repeat step 2 once if anything changed. PRUNE and NIT findings never enter the fix step.
4. A claim that a review comment is "already fixed at HEAD" gets the live PR-head check only when the branch is pushed. Use `gh pr view <n> --json headRefOid` and the thread state. When the branch is not pushed, trust the child's tree check.
5. A child that says a test or check "cannot fail" must prove it: run it once on the change, once with the change reverted, and quote both outputs. The brief names both runs. Require the reverted run only for claims that gate a fix.
6. No goalpost moving: the full rule is in `references/review-loop-rules.md`.
7. Shipped-repo check: grep the reviewed diff for machine-specific text (`$HOME`, `/home/<user>` paths, the user name, host names) in files that ship. Fold the grep into the reviewer prompt and skip it for diffs that touch no shipping file.
Report: the decision-log table, the reviewer verdicts, and the final check results (with exit codes).
